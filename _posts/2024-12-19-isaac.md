This note records an Isaac Sim 4.2 installation from December 2024. The commands refer to the repository layouts and package versions used then; newer Isaac Lab releases may organize their tutorials differently.

I started with a Python environment containing PyTorch and CUDA support. One version recorded in my notes was:

```bash
pip install torch==2.4.0 --index-url https://download.pytorch.org/whl/cu118
```

For the complete setup requirements, see the [Isaac Lab pip installation guide](https://isaac-sim.github.io/IsaacLab/main/source/setup/installation/pip_installation.html).

## Install Isaac Sim

The full version-pinned installation was:

```bash
pip install --upgrade pip
pip install \
  isaacsim==4.2.0.2 \
  isaacsim-extscache-physics==4.2.0.2 \
  isaacsim-extscache-kit==4.2.0.2 \
  isaacsim-extscache-kit-sdk==4.2.0.2 \
  --extra-index-url https://pypi.nvidia.com
```

I also recorded a component-based alternative for the functionality I needed:

```bash
pip install isaacsim-rl isaacsim-replicator isaacsim-extscache-physics \
  isaacsim-extscache-kit-sdk isaacsim-extscache-kit isaacsim-app \
  --extra-index-url https://pypi.nvidia.com
```

That alternative is unpinned, so it is not an exact recreation of the versioned environment above. Check that the selected component versions are compatible before combining them.

Launch the application to check startup:

```bash
isaacsim
# When intentionally running as root in a container:
isaacsim --allow-root
```

The first launch asks for acceptance of NVIDIA's license agreement. It can then spend considerable time resolving and downloading extensions. My log progressed from:

```text
Failed to solve some dependencies locally, syncing with extension registry...
```

to:

```text
[7042.715s] [ext: omni.app.mini-0.1.1] startup
[7042.733s] app ready
```

The initial startup took much longer than I expected; the final `app ready` line was the useful signal.

## Clone and install Isaac Lab

Public repositories can be cloned over HTTPS without configuring an SSH key:

```bash
git clone https://github.com/isaac-sim/IsaacLab.git
sudo apt install cmake build-essential
cd IsaacLab
```

An SSH clone instead uses a key registered with your own GitHub account. My original note confused this with adding a key to someone else's repository.

If the helper script is not executable, give that file execute permission:

```bash
chmod +x isaaclab.sh
```

Install all supported learning frameworks, or select one:

```bash
./isaaclab.sh --install
# Alternative: install only rl_games.
./isaaclab.sh --install rl_games
```

Other choices in the version I used included `rsl_rl`, `sb3`, `skrl`, `robomimic`, and `none`.

I verified the installation with the empty-scene tutorial:

```bash
./isaaclab.sh -p source/standalone/tutorials/00_sim/create_empty.py
# Or, from the configured virtual environment:
python source/standalone/tutorials/00_sim/create_empty.py
```

## Robot Lab examples

I then followed [Robot Lab](https://github.com/fan-ziqi/robot_lab), cloning it separately from the Isaac Lab checkout:

```bash
cd ..
git clone https://github.com/fan-ziqi/robot_lab.git
cd robot_lab
python -m pip install -e ./exts/robot_lab
python scripts/tools/list_envs.py
```

The interpreter used for the editable installation must be the one configured for Isaac Lab. The following commands are examples saved from that setup:

```bash
python scripts/rsl_rl/base/train.py \
  --task RobotLab-Isaac-Velocity-Flat-Unitree-G1-v0 \
  --headless --video --video_length 100 --video_interval 500 \
  --num_envs 32 --max_iterations 10000

python3 scripts/rsl_rl/train.py \
  --task Template-Isaac-Reach-UR10-v0 \
  --num_envs 4096 --headless --video --video_length 100 \
  --max_iterations 10
```

The first is a Unitree G1 locomotion task; the second is a UR10 reaching task. Their task names and entry points depend on the corresponding extension version.
