A labmate arranged access to an Ubuntu server and gave me a user account. My first question was how to run experiments without disrupting everyone else's environment or jobs. These are the practices and small scripts I collected while using the shared A800 machine.

## Start with your own shell configuration

A minimal `$` prompt can simply mean the account is using a minimal shell configuration. To work in Bash:

```bash
bash
```

Keep environment changes in your own `~/.profile` or `~/.bashrc`. Editing `/etc/profile`, `/etc/bashrc`, or another global configuration can affect every user. Installing Conda in your own home directory is different from replacing system CUDA libraries or a GPU driver.

## Select an existing CUDA toolkit

I used the toolkit installations already maintained under `/usr/local`. The helper below lists them when sourced without an argument and selects one for the current shell when given a version:

```bash
source switch-cuda.sh
source switch-cuda.sh 12.4
```

For example, the machine had `cuda-11.0` and `cuda-12.4`. Save this as `switch-cuda.sh`:

```bash
#!/usr/bin/env bash

# Source this file so the environment changes affect the current shell.
if [[ "${BASH_SOURCE[0]}" == "${0}" ]]; then
    echo "Please use 'source switch-cuda.sh [VERSION]'."
    exit 1
fi

cuda_install_folder="/usr/local"
cuda_target_version="${1:-}"

if [[ -z "$cuda_target_version" ]]; then
    echo "CUDA installations in ${cuda_install_folder}:"
    for cuda_candidate in "$cuda_install_folder"/cuda-[0-9]*; do
        [[ -d "$cuda_candidate" ]] && echo "* ${cuda_candidate##*/}"
    done
    return 0
fi

cuda_selected_path="$cuda_install_folder/cuda-$cuda_target_version"
if [[ ! -d "$cuda_selected_path" ]]; then
    echo "CUDA ${cuda_target_version} was not found."
    return 1
fi

# Remove old toolkit paths while retaining other entries.
IFS=: read -r -a cuda_path_entries <<< "$PATH"
cuda_new_path="$cuda_selected_path/bin"
for cuda_entry in "${cuda_path_entries[@]}"; do
    [[ "$cuda_entry" == "$cuda_install_folder"/cuda* ]] && continue
    cuda_new_path+=":$cuda_entry"
done

IFS=: read -r -a cuda_library_entries <<< "${LD_LIBRARY_PATH:-}"
cuda_new_library_path="$cuda_selected_path/lib64:$cuda_selected_path/extras/CUPTI/lib64"
for cuda_entry in "${cuda_library_entries[@]}"; do
    [[ -z "$cuda_entry" || "$cuda_entry" == "$cuda_install_folder"/cuda* ]] && continue
    cuda_new_library_path+=":$cuda_entry"
done

export CUDA_HOME="$cuda_selected_path"
export CUDA_ROOT="$cuda_selected_path"
export PATH="$cuda_new_path"
export LD_LIBRARY_PATH="$cuda_new_library_path"
echo "Switched to CUDA ${cuda_target_version}."
```

This selects a toolkit for the shell; it does not change the system driver or guarantee that a particular PyTorch build uses that toolkit. The script is a cleaned-up version of the helper in my original note, without changing the shell's global `errexit` setting.

## Install Conda for your account

I preferred Miniconda for its smaller initial footprint:

```bash
mkdir -p ~/miniconda-installer
cd ~/miniconda-installer
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh
```

After installing to the default location:

```bash
eval "$("$HOME/miniconda3/bin/conda" shell.bash hook)"
conda init bash
```

The installer and `conda init` can update your own shell configuration. Choose package channels within that environment as needed. System packages installed through APT still normally require administrator access; selecting a different mirror does not remove that requirement.

## Find out who is using a GPU

A continuously refreshed status view is useful before starting a job:

```bash
watch -n 2 -d nvidia-smi
```

Given a process ID from the output, inspect its owner and start time:

```bash
ps -p PID -o user=,lstart=
```

I also used a small script to put process ownership beside the GPU index. Save it as `check.sh`, then run `bash check.sh`:

```bash
#!/usr/bin/env bash

pids=$(nvidia-smi --query-compute-apps=pid --format=csv,noheader | sort -u)
if [[ -z "$pids" ]]; then
    echo "No compute processes are running on the GPU."
    exit 0
fi

printf "%-10s %-20s %-25s %s\n" "PID" "USER" "STARTED" "GPU"
while IFS= read -r pid; do
    process_user=$(ps -p "$pid" -o user=)
    process_started=$(ps -p "$pid" -o lstart=)
    gpu_index=$(nvidia-smi pmon -c 1 | awk -v pid="$pid" '$2 == pid {print $1}')
    printf "%-10s %-20s %-25s %s\n" \
      "$pid" "$process_user" "$process_started" "$gpu_index"
done <<< "$pids"
```

A process can exit between queries, and visibility depends on the server configuration. The point is to identify the owner and coordinate GPU usage, rather than terminate someone else's training job.
